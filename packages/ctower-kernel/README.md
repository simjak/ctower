# ctower-kernel boundary

Future trusted modular-monolith artifact. Its I1/I2 deep Modules are Access, Record, Catalog, Work, Proof,
Attention, Runtime, Effects, Workflow, and Projections, plus a declarative extension registry whose content
is inert package data. There is no executable Extension Host in I1 or I2; that runtime remains deferred until
a real use case and two real Adapters earn its Seam. The kernel may depend on authored/generated contracts
and allowlisted public Module Interfaces, never on apps, runner/provider implementations, web, CLI, or
mutable YAML state.
