# Security policy

## Supported versions

ctower has no released runtime yet. The repository is pre-alpha, and `main` is the only branch receiving
security corrections. A supported-version table will be added with the first SemVer release.

## Report a vulnerability privately

Do **not** open a public issue, discussion, or pull request. Use GitHub's private vulnerability-reporting
form:

<https://github.com/simjak/ctower/security/advisories/new>

Include only what maintainers need to reproduce and assess the issue:

- the affected commit or release;
- the preconditions and impact;
- minimal reproduction steps or a proof of concept;
- any known exposure or workaround;
- a safe way to contact you for follow-up.

Never include real credentials, personal data, customer data, or private infrastructure details. Use
synthetic values and attach sensitive material only through the private report.

If private reporting is unavailable, contact the maintainer through a private method listed on the
[`@simjak`](https://github.com/simjak) GitHub profile and mention **ctower security**. Do not send technical
details over a public channel merely to request contact.

Maintainers will validate the report, coordinate a fix and disclosure plan, and credit reporters who want
credit. No response-time SLA applies before the first supported release, but private reports are treated as
release blockers once confirmed.
